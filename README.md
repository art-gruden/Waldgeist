# Waldgeist · Enchanted Companions 🌲

Затишна Telegram-гра для закритої групи онлайн-занять: кожен учасник має чарівного компаньйона. Компаньйон росте, коли власник вітається зранку, приходить на заняття й ходить у гості. Покарань немає: без активності компаньйон просто засинає й нічого не втрачає.

Ігрові правила описані в GDD, технічні рішення — у специфікації (обидва документи — артефакти Claude). Цей репозиторій реалізує **MVP (фази 1–5 специфікації + візити)**.

## Що вміє бот

| Функція | Як працює |
| --- | --- |
| Реєстрація | `/start` в особистому чаті, лише для учасників групи; 16 видів, кожен вид може обрати лише одна людина; ім'я компаньйона; день народження за бажанням |
| Ранок | О 07:00 листівка в групі з кнопкою; з 05:00 до 12:00 зараховується кнопка або повідомлення з привітанням (UK/RU/EN/DE): +10, раз на день; о 12:30 підсумок без списку відсутніх |
| Рівні | 10 рівнів, 4 стадії (Малюк → Юний → Дорослий → Легендарний хранитель); рівень ніколи не знижується |
| Сон | Компаньйон дрімає після 2 днів без активності, спить після 4, бачить чарівні сни після 8. Будь-яка дія його будить. Після 7 днів надсилається одне м'яке нагадування |
| Заняття | Адмін створює заняття з кодовим словом; живе заняття +30 до кінця дня, запис +15 протягом 7 днів (на одне заняття — щось одне з двох); анонси за 24 год і 1 год; вечірня подяка в групі |
| Візити | Раз на день: господар +20, гість +3. Хто сам у гостях (60 хв), того «вдома нікого не було», і спроба гостя не згоряє. Гість тваринки @omniyaskala отримує афірмацію або духовний закон без повторів |
| Дашборди | `/world` — ліс і спільнота, `/stats` — особиста статистика, `/help` |
| Адмінка | Заняття, ручні відмітки, нарахування й скасування енергії з причиною, зміна виду, оголошення, `/chatid` |

Наступні фази — догляд, SPA, подорожі, досягнення, квести, подяки, свята. Команди `/activities` і `/quests` поки відповідають «скоро».

## Структура

```text
Waldgeist/
├── config/game.yaml          # УВЕСЬ баланс і розклад — змінюється без коду
├── content/uk/
│   ├── texts.yaml            # усі тексти бота (кілька варіантів на ситуацію)
│   ├── species.yaml          # 16 видів
│   └── affirmations.yaml     # афірмації й закони Омнії (скопіювати, див. нижче)
├── assets/images/            # <slug>/stage-1..4.jpg, <slug>/sleep.jpg, locations/<scene>.jpg
├── src/enchanted_companions/
│   ├── app.py                # запуск, коректна зупинка
│   ├── settings.py           # .env + game.yaml з валідацією
│   ├── domain/               # чисті правила без I/O: час, рівні, сон, привітання, афірмації
│   ├── db/                   # моделі, репозиторії, міграції Alembic, seed видів
│   ├── services/             # сценарії; reward_engine — єдина точка нарахування енергії
│   ├── bot/                  # обробники aiogram, клавіатури, callback-дані, middlewares
│   └── scheduler/            # APScheduler: листівка, підсумок, сон, заняття, heartbeat
├── tests/                    # 131 тест: unit + інтеграційні (сервіси й Telegram-сценарії)
├── install.sh                # встановлення на сервері після git clone
├── update.sh                 # оновлення: бекап → git pull → перезапуск
├── deploy/                   # deploy (rsync), backup, restore, systemd-юніт
├── Dockerfile
└── docker-compose.yml        # bot + PostgreSQL 16 + щоденні бекапи
```

**Надійність.** Кожна нагорода має ключ ідемпотентності з UNIQUE в БД: подвійна кнопка, гонка запитів чи рестарт не дадуть подвійних нарахувань. Рядок тваринки блокується (`SELECT … FOR UPDATE`) у тій самій транзакції, де пишеться журнал енергії. Щоденні задачі спершу «захоплюють» запис у `job_runs`, тому не виконуються двічі навіть після рестарту. Повідомлення надсилаються лише після коміту; при flood-control Telegram бот повторює запит.

## Налаштування

### `.env` (секрети, не в git)

| Змінна | Що це |
| --- | --- |
| `BOT_TOKEN` | Токен від @BotFather |
| `GROUP_CHAT_ID` | ID групи (від'ємне число). Додайте бота в групу, напишіть там `/chatid` від імені адміна |
| `ADMIN_TG_IDS` | `835852842,2116564097` — @artgruden і @omniyaskala |
| `POSTGRES_PASSWORD` | Генерує `install.sh` |
| `BACKUP_TIME`, `BACKUP_KEEP_DAYS` | Час щоденного бекапу (за Києвом) і скільки днів зберігати |

### Ігровий баланс — `config/game.yaml`

Енергія за дії, пороги рівнів, ранкове вікно, сон, заняття, візити, часовий пояс (`Europe/Kyiv`). Після зміни: `docker compose restart bot`.

### Тексти — `content/uk/texts.yaml`

Усі повідомлення бота. Якщо ключ містить список, бот обирає варіант випадково. Слова у `{дужках}` підставляє бот, їх лишаємо. Розмітка — Telegram HTML (`<b>`, `<i>`).

### Афірмації — `content/uk/affirmations.yaml`

Скопіюйте сюди готовий файл із папки `shlyah-ukr` (45 афірмацій, 49 законів, шаблони постів). Бот читає його без змін. Поки файлу немає, візити до тваринки Омнії працюють, але без афірмацій (у лозі буде попередження).

### Зображення — `assets/images/`

`fox/stage-1.jpg` … `stage-4.jpg`, `fox/sleep.jpg`, `locations/heart.jpg` (ранкова листівка). Підходять `.jpg`, `.png`, `.webp`. Якщо зображення стадії немає, бот бере попередню стадію; якщо немає жодного — показує профіль текстом. Список відсутніх зображень дає команда `/missing_images`. Telegram `file_id` кешується, тому кожен файл завантажується лише раз.

Зараз бракує 18 зображень тварин (серед них `otter/stage-1`, `fox/sleep`, увесь `forest_cat`, `firefly_fairy/stage-2…4`) і 6 сцен — повний список дає `/missing_images`, команди генерації — у `docs/image-brief.md`.

## Деплой на Ubuntu-сервер із Galene

Бот **не відкриває жодного порту**. Він сам звертається до Telegram (long polling, вихідний HTTPS), а PostgreSQL доступний лише у внутрішній Docker-мережі. Тому Galene, його порти (HTTPS і TURN), сертифікати й firewall залишаються незмінними. Ліміти пам'яті й CPU контейнерів (бот 256 МБ / 0,5 CPU, БД 256 МБ / 0,5 CPU) не дають грі забирати ресурси відеозв'язку.

1. **Telegram:** створіть бота в @BotFather і додайте його в групу **адміністратором** — так він бачить повідомлення («доброго ранку») і може ставити реакції.
2. **Встановлення на сервері одразу після клонування:**
   ```bash
   sudo git clone https://github.com/<ваш-акаунт>/Waldgeist.git /opt/waldgeist
   cd /opt/waldgeist
   sudo ./install.sh
   ```
   `install.sh` встановить Docker і Compose v2 (якщо їх немає), створить `.env` з випадковим паролем БД, запитає токен бота й ID групи (ID можна пропустити), перевірить токен у Telegram, увімкне автозапуск через systemd, збере образ і запустить стек. Без запитань: `sudo BOT_TOKEN=... GROUP_CHAT_ID=-100... ./install.sh`. Для приватного репозиторію на сервері потрібен deploy key або токен GitHub.
3. **ID групи:** якщо пропустили — напишіть у групі `/chatid` (від імені адміна), потім `sudo GROUP_CHAT_ID=-100... ./install.sh`.
4. **Афірмації та зображення** (`content/uk/affirmations.yaml`, нові картинки в `assets/images/`) — закомітьте в репозиторій або скопіюйте на сервер, потім `docker compose restart bot`.
5. **Оновлення:** `cd /opt/waldgeist && sudo ./update.sh` — бекап бази, `git pull`, перезбирання й перезапуск. `.env`, `data/` (база й бекапи) і `logs/` не відстежуються git і не змінюються.

Альтернатива без GitHub на сервері: `./deploy/deploy.sh user@server /opt/waldgeist` копіює робочу папку з Mac через rsync, після чого на сервері `sudo ./install.sh`.

Стек стартує після перезавантаження сервера (systemd-юніт `enchanted-companions.service` + `restart: unless-stopped`).

### Експлуатація

```bash
cd /opt/waldgeist
docker compose ps                         # стан і healthcheck
docker compose logs -f bot                # JSON-логи (секрети маскуються); також logs/bot.log
docker compose exec backup sh /backup.sh now   # бекап зараз → data/backups/
sudo ./deploy/restore.sh data/backups/enchanted-YYYYMMDD-HHMMSS.dump
docker compose restart bot                # після зміни game.yaml / texts.yaml / зображень
```

Бекап створюється щодня о 03:30 за Києвом, зберігаються 14 днів. Варто періодично копіювати `data/backups/` за межі сервера (наприклад, `rsync` на Mac).

### Команди адміністратора (`/admin`)

## Розробка

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.lock -e ".[dev]"
docker compose -f docker-compose.dev.yml up -d       # PostgreSQL на localhost:5432
cp .env.example .env    # BOT_TOKEN тестового бота, DATABASE_URL=postgresql+asyncpg://ec:devpassword@localhost:5432/enchanted
alembic upgrade head
python -m enchanted_companions
```

Тести (на PostgreSQL, як у продакшені; без `TEST_DATABASE_URL` — на SQLite):

```bash
TEST_DATABASE_URL=postgresql+asyncpg://ec:devpassword@localhost:5432/enchanted pytest -q
ruff check src tests && ruff format --check src tests
```

Нова міграція після зміни моделей: `alembic revision --autogenerate -m "опис"`. Перевіряйте згенерований файл перед комітом. GitHub Actions (`.github/workflows/ci.yml`) проганяє ruff, тести на PostgreSQL, міграції та `docker build`.

## Відомі обмеження

- Стан незавершених діалогів (реєстрація, майстер заняття) зберігається в пам'яті. Після рестарту такий діалог треба почати заново (`/start`, `/new_class`); ігрові дані не губляться.
- Реакція для запрошення новачка — 🕊: Telegram не дозволяє ботам ставити 🌱. Емодзі змінюється в `game.yaml`.
- Розрахована одна інстанція бота: друга отримає конфлікт polling від Telegram, але подвійних нарахувань і подвійних розсилок не буде.
