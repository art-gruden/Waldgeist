# Telegram-бот «Енергозавантаження»: листівки з текстом

Надсилаєте боту текст (10–20 слів українською), отримуєте листівку: фон із шаблону, заголовок (типово **ЕНЕРГОЗАВАНТАЖЕННЯ**), текст зі світінням, за бажанням підпис. Типовий розмір **1280×782**. Усе налаштовується в меню бота; нові шаблони додаються фотографією прямо в чаті; готову листівку одним натисканням можна опублікувати у ваш Telegram-канал. Працює в Docker, без зовнішніх сервісів, крім самого Telegram: рендер локальний (Pillow), шрифти й фони в образі.

```
Telegram ⇄ bot (python-telegram-bot, long polling) ──► textcard (Pillow) ──► фото / файл
                     │
                     ├── /data: bot.sqlite3 (налаштування, доступ, підключені канали) + templates/ (додані фото-шаблони)
                     └── 📢 кнопка «Опублікувати» ──► ваш Telegram-канал (бот — адміністратор каналу)
```

## Швидкий старт

1. У Telegram напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримайте токен.
2. На сервері:
   ```bash
   unzip textcard-bot.zip && cd textcard-bot
   cp .env.example .env          # впишіть BOT_TOKEN=...
   docker compose up -d --build
   docker compose logs -f        # «бот @… запущено»
   ```
3. Напишіть боту `/start`. **Перший, хто напише, стає адміністратором**, якщо в `.env` не задано `ADMIN_IDS`. Щоб адміна не «перехопили», задайте свій ID одразу (дізнатися: команда `/id` у боті або [@userinfobot](https://t.me/userinfobot)).

Порти відкривати не треба: бот сам опитує Telegram (long polling).

Оновлення: `docker compose up -d --build` (налаштування, підключені канали й додані шаблони лежать у томі `bot-data` і зберігаються; стара база сама доповнюється трьома колонками для публікації, дані не втрачаються).
Резервна копія: `docker compose cp bot:/data ./backup-data`.

## Як користуватися

- **Текст** → листівка. `*слово*` виділяє слово акцентним кольором. Переноси рядків зберігаються.
- **Разовий заголовок**: перший рядок починається з `#`:
  ```
  # Ранкова практика
  Я відкриваю своє серце присутності Творця…
  ```
  Лише `#` без тексту дає листівку без заголовка.
- **Кнопки під листівкою**: 🔄 інший шаблон (наступний по колу), 🖼 вибрати шаблон, 📐 інший розмір, 📄 надіслати файлом, 📢 опублікувати в канал. Листівка перемальовується з тим самим текстом.
- **Фото, надіслане боту**, → новий шаблон: назва → стиль тексту (як у якому з наявних шаблонів) → обробка фону (без змін / затемнити / освітлити / темна чи світла панель під текстом). Фото краще надсилати **файлом** (📎 → Файл), бо стиснуте Telegram має лише до 1280 px.

Команди: `/menu` (налаштування), `/templates`, `/channel` (канал для публікацій), `/title текст`, `/help`, `/cancel`, `/id`, `/start`.

## Публікація в Telegram-канал

Канал підключає кожен користувач сам, і лише такий, де він є адміністратором.

1. Додайте бота **адміністратором** свого каналу з правом **«Публікація повідомлень»** (для групи достатньо, щоб бот був адміністратором).
2. У боті: `/menu` → **📢 Канал** → **➕ Підключити канал** (або команда `/channel`). Перешліть боту будь-який пост із каналу, або надішліть `@username`, посилання `t.me/…` чи числовий ID (`-100…`).
3. Бот перевіряє, що він і ви адміністратори, і запам'ятовує канал (налаштування на користувача; «Скинути все» його не відключає, відключити можна кнопкою 🔌).

Після цього:

- **📢 Опублікувати в канал** під листівкою надсилає в канал саме цю картинку (без підпису), а вам повертає посилання на пост.
- **📢 Опублікувати останню** в головному меню публікує вашу останню листівку.
- Листівка-файл (📄) публікується як файл; у режимі «фото + файл» публікується фото.
- Захист від випадкових дублів: якщо листівка вже в цьому каналі, бот перепитує «Опублікувати ще раз?». У інший канал вона йде без запитання.
- Перед кожною публікацією перевіряється, що ви досі адміністратор каналу. Якщо бота видалили з каналу чи забрали право публікувати, бот пише, що канал треба перепідключити.

## Меню налаштувань (`/menu`)

Налаштування в кожного користувача свої й зберігаються між перезапусками.

| Пункт | Що змінює |
|---|---|
| 🖼 Шаблон | фон і стиль; «👁 Приклади» надсилає альбом усіх шаблонів з вашим заголовком |
| 🏷 Заголовок | текст (типово ЕНЕРГОЗАВАНТАЖЕННЯ), показувати чи ні, повернути типовий, шрифт заголовка |
| ✍️ Підпис | рядок унизу (сайт, ім'я) або без нього |
| 📐 Розмір | 1280×782 (типовий), 16:9 1280×720, 1600×978, квадрат 1080×1080, пост 1080×1350, сторіс 1080×1920 або свій `ШИРИНАxВИСОТА` (200…4096) |
| 🔤 Шрифт | шрифт тексту: як у шаблоні або один із 9 з українською абеткою |
| 🎨 Колір | як у шаблоні, білий, вишневий, фіолетовий, темно-синій, чорний, золотий (акцент і світіння підбираються в пару) |
| ✨ Світіння | увімкнути / вимкнути |
| 📤 Надсилати | фото (Telegram стискає), файл (PNG або JPEG без втрат), фото + файл |
| 📢 Канал | підключити / змінити / відключити канал для публікацій; «Опублікувати останню» |
| 🗂 Шаблони | додати шаблон із фото, видалити власні, приклади |
| ↩️ Скинути все | повернути типові налаштування |
| 🛠 Адміністрування | лише для адмінів, див. нижче |

### Адміністрування

- **Хто користується ботом**: усі (типово) або лише дозволені. Якщо доступ закритий, невідомий користувач бачить свій ID, а адміни отримують запит із кнопками ✅ Дозволити / 🚫 Відхилити.
- **Хто додає шаблони**: лише адміни (типово) або всі. Видаляти можна свої шаблони, адміни — будь-які додані. Вбудовані не видаляються.
- **Користувачі**: останні 25, дозволити/заборонити, зробити адміном. **Дозволити за ID** — якщо людина ще не писала боту.
- **Мої налаштування → типові**: нові користувачі (і ті, хто натисне «Скинути все») отримають ваші шаблон, заголовок, розмір, підпис тощо.

## `.env`

| Змінна | За замовч. | |
|---|---|---|
| `BOT_TOKEN` | — | обов'язково |
| `ADMIN_IDS` | порожньо | ID адмінів через кому; порожньо — адміном стає перший користувач |
| `DEFAULT_TITLE` / `DEFAULT_SIZE` / `DEFAULT_TEMPLATE` | `ЕНЕРГОЗАВАНТАЖЕННЯ` / `1280x782` / `pink_glow` | стартові значення; далі все змінюється в меню |
| `MAX_WORDS` / `MAX_CHARS` | 40 / 400 | ліміти тексту |
| `MAX_UPLOAD_MB` | 20 | ліміт фото для шаблону (Bot API більше ботам і не віддає) |
| `RENDER_CONCURRENCY` | 2 | одночасних рендерів |
| `TELEGRAM_API_URL`, `TELEGRAM_FILE_URL` | — | власний сервер Bot API (зазвичай не потрібно) |
| `LOG_LEVEL` | `INFO` | у лог пишуться лише ID користувачів і дії, без текстів і без токена |

## Шаблони

18 вбудованих (у меню вони йдуть двома сторінками по 10).

- **Перші 8**: Рожеве сяйво (типовий), Захід сонця, Морські промені, Лавандові хмари, Нічне небо, Сонце в лісі, Золоте боке, Старий папір.
- **10 яскравих, що піднімають настрій**: Лимонне сонце (`lemon_sun`), Кораловий ранок (`coral_sky`), Бірюзова лагуна (`turquoise_lagoon`), Весняна зелень (`spring_green`), Медовий ранок (`honey_morning`), Райдужне боке (`rainbow_bokeh`), Помаранчевий світанок (`orange_dawn`), Квітуча вишня (`cherry_blossom`), Блакитне небо (`blue_sky`), Золотий полудень (`golden_noon`). Усі світлі, з темним текстом і білим або світлим ореолом; контраст тексту до фону в рамці тексту скрізь не нижчий за 6,4 (норма читабельності — 4,5).

Фони згенеровані скриптом `textcard/make_backgrounds.py` (`python3 textcard/make_backgrounds.py` — усі, `… lemon_sun` — один; для яскравих десяти він пише й `template.json`, стилі в словнику `CONFIGS`). Додані через бота шаблони лежать у `/data/templates/<id>/` (`background.jpg` + `template.json`). Формат `template.json` (рамка тексту, кольори, світіння, панель) описано в README сервісу textcard; файл можна поправити вручну й перезапустити бота.

## Тести

```bash
pip install -r requirements-dev.txt
python3 tests/test_render.py     # 13 тестів рендера: типографіка, перенос, усі 18 шаблонів × усі розміри
python3 tests/test_bot.py        # 109 наскрізних перевірок проти імітації Telegram Bot API (tests/fake_tg.py)
```

`test_bot.py` піднімає локальну імітацію Bot API і проходить сценарії: `/start` і призначення адміна, листівка 1280×782, усі пункти меню, свій розмір, заголовок (змінити / сховати / типовий / `/title` / разовий `#`), кнопки під листівкою, фото + файл JPEG, шрифти й кольори, альбом прикладів, помилки тексту, додавання шаблону з файлу й зі стиснутого фото, `/cancel`, замале фото, не-зображення, видалення, права звичайного користувача, закритий доступ (запит → схвалення → заборона → дозвіл за ID), адмінство, типові налаштування для нових, збереження після перезапуску. Для каналів: підключення (помилки: не канал, бот не адмін, немає права публікувати, ви не адмін; успіх за `@username`, числовим ID групи й пересланим постом, зокрема з картинкою), публікація з-під листівки й з меню (перевіряється, що в канал іде та сама картинка), файл, захист від дублів, відібрані права, чужий канал, відключення, міграція старої бази.

## Що перевірено, а що ні

**Перевірено в пісочниці (Python 3.13, python-telegram-bot 22.8, Pillow 12.3):** обидва набори тестів (наскрізний — 4 прогони поспіль без збоїв); справжня точка входу `python -m bot.main` (`run_polling`, реєстрація команд разом із `/channel`, відповідь на `/start`, `/channel` і текст) проти імітації API; токен і тексти не потрапляють у лог; усі 10 нових фонів переглянуто у форматах 1280×782 і 1080×1920.

**Не перевірено:** справжній Telegram (api.telegram.org із пісочниці недоступний: імітація повторює формат Bot API, але не всі його обмеження). Для каналів це означає, що поведінку прав (`getChatMember`, право «Публікація повідомлень») і повторне надсилання картинки за `file_id` у канал перевірено на імітації, а не на живому каналі: перший раз підключіть тестовий канал і натисніть «Опублікувати». Збірка Docker-образу теж не перевірялась (Docker Hub недоступний). Перший запуск: `docker compose logs -f`, далі `/start` у боті.

## Обмеження

- Лише приватні чати; у групах бот мовчить (публікувати в групу можна, але керується ботом лише з особистого чату).
- Публікація в канал: тільки картинка (без підпису й хештегів), один канал на користувача.
- Емодзі не малюються (у шрифтах їх немає): бот пропускає їх і пише про це в підписі до фото.
- Кнопки під старими листівками працюють для останніх 200 листівок кожного користувача.
- Один процес і SQLite: для одного-кількох десятків активних користувачів цього досить; рендер займає ≈0,1–0,3 с.
